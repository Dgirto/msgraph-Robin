¿Qué es y para qué sirve?

El conector Microsoft 365 permite que el agente de Ruvic opere sobre Microsoft Graph: leer y enviar correo de Outlook, leer y escribir archivos en OneDrive (incluido Excel), enviar mensajes y crear reuniones en Teams, y suscribirse a notificaciones push. Librería: msgraph-client (Dgirto/msgraph-Robin).

Operaciones soportadas:

Operación Qué hace
email.readLee correos de un buzón (filtros, adjuntos)
email.sendEnvía correo desde un buzón de la organización
drive.readLista y descarga archivos de OneDrive / lee rangos de Excel
drive.writeSube archivos y escribe celdas o filas en Excel
teams.messageEnvía mensajes a un canal o chat
teams.meetingCrea reuniones en línea
webhooks.subscribeCrea, renueva o elimina suscripciones de Graph

Aplicación, no usuario interactivo Usa el flujo client credentials de Entra ID (aplicación). No hay pantalla de “iniciar sesión con Microsoft” en cada ejecución.

Prerrequisitos

  • Un inquilino de Microsoft 365 / Entra ID y permiso de administrador para registrar aplicaciones y otorgar consentimiento.
  • Los buzones, OneDrive o sites que el agente vaya a usar deben existir en ese inquilino.
  • En Ruvic: Settings → Conectores → Microsoft 365 (Graph API).

Configuración en el fabricante

Registra una aplicación en Azure / Entra ID, crea un secreto y concede permisos de aplicación de Microsoft Graph con consentimiento de administrador.

  1. Registrar la aplicación: En Azure Portal → Microsoft Entra ID → App registrations → New registration. Nombre p. ej. Ruvic Graph. Tipo de cuenta: Accounts in this organizational directory only.
  2. Anotar IDs: En Overview copia Application (client) ID y Directory (tenant) ID.
  3. Crear un secreto: Certificates & secrets → New client secret. Copia el Value (solo se muestra una vez). No copies el Secret ID.
  4. Permisos de Graph: API permissions → Add a permission → Microsoft Graph → Application permissions. Añade los de la tabla de Permisos. Luego Grant admin consent.

Permisos requeridos

Permisos de aplicación (no delegated). Concede solo los que vaya a usar el agente. Todos requieren admin consent en el inquilino.

Configuración en Ruvic

  1. Abrir el conector: Settings → Conectores → Microsoft 365 (Graph API).
  2. Modo de autenticación: Aplicación de Azure (client credentials).
  3. Pegar credenciales: Client ID, Client Secret y Tenant ID. Opcional: buzón por defecto (robot@empresa.com).
  4. Variables en runtime: RUVIC_MSGRAPH_CLIENT_ID, RUVIC_MSGRAPH_CLIENT_SECRET, RUVIC_MSGRAPH_TENANT_ID y RUVIC_MSGRAPH_DEFAULT_MAILBOX.

Verificación

Pulsa Probar conexión. Ruvic pide un token de aplicación y consulta GET /v1.0/organization. Si responde el nombre del inquilino, las credenciales son válidas. Si el token se obtiene pero GET /organization devuelve 403, concede Organization.Read.All o Directory.Read.All.

La librería se instala con:

pip install git+https://github.com/Dgirto/msgraph-Robin.git

Este repo no usa #subdirectory=lib: el paquete está en la raíz.

Solución de problemas

invalid_client / secret

El secreto expiró o se copió el Secret ID en lugar del Value.

unauthorized_client / AADSTS700016

Client ID o Tenant ID incorrectos.

403 Insufficient privileges

Faltan permisos de aplicación o no se otorgó admin consent.

Mailbox not found

El buzón no existe o la app no tiene Mail.Read / Mail.Send sobre ese usuario.

ImportError msgraph_client

Reinstala con la URL de GitHub (sin lib/).

Preguntas frecuentes y notas de seguridad

¿Por qué no OAuth de usuario?

Este conector está pensado para automatizaciones de servicio (client credentials). No guarda refresh tokens de un usuario final.

¿El secreto se muestra en Settings?

No: se guarda como secreto y solo indica si está definido.

¿Hay que pegar el client_secret en el código del agente?

Nunca. El agente lee RUVIC_MSGRAPH_CLIENT_SECRET del entorno. GraphAuth se instancia con os.environ, no con literales.

¿El Incoming Webhook de Teams usa estas credenciales?

No. send_webhook_message usa la URL del conector Incoming Webhook del canal y no requiere permisos de Graph.
